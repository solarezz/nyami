# Roadmap — «Редизайн + фундамент», затем «Полная фитнес-платформа»

Этапы 1–4 ниже выполнены в рамках первоначального объёма («Редизайн + фундамент»,
решение от 2026-11-09). 2026-11-13 объём пересмотрен (`PRODUCT_DECISIONS.md`): старый
Этап 5 («подходы без библиотеки упражнений») заменён полноценным тренировочным
модулем, добавлен Этап 7 (редизайн v2 — жёсткий спортивный стиль вместо мягкого).

Порядок этапов — от фундамента к видимому результату, т.к. часть редизайна
(добавление еды по ингредиентам, подходы в тренировках) физически зависит от новой
схемы БД. Каждый этап — отдельные коммиты, после каждого — typecheck/build, ручная
проверка сценария.

## Этап 1 — Фундамент данных (невидим пользователю)

- Таймзона: `users.timezone`, централизованные хелперы локальной даты, замена
  захардкоженного `+03:00`, определение таймзоны в онбординге.
- `daily_targets`: таблица, запись при каждом сохранении профиля, `getDay` читает
  цель на дату, а не текущую.
- Тесты (unit) на то, что сейчас совсем не покрыто и больнее всего ломается молча:
  расчёт нормы (`nutrition.ts`), границы дня в разных таймзонах/DST, пересчёт
  `meal_items` → агрегат приёма пищи.

Критерий готовности: исторические дни показывают ту цель, что действовала тогда;
смена системной таймзоны сервера не меняет границы «сегодня» для пользователя.

## Этап 2 — Ингредиенты в еде

- Миграция `meal_items` (backfill существующих `meals`).
- API: `POST /api/meals` принимает список компонентов; `PATCH` компонента
  пересчитывает агрегат приёма пищи.
- AI-распознавание: `extras` становятся полноценными редактируемыми компонентами
  результата (экран Result), а не довеском без возможности править граммовку.
- Фронт: карточка приёма пищи раскрывается в список компонентов; можно поменять
  массу одного компонента — агрегат приёма обновляется.

Критерий готовности: бургер (булочка+мясо+сыр) можно добавить одним приёмом,
поменять массу мяса — итог по приёму пересчитывается, остальные компоненты не трогает.

## Этап 3 — Дизайн-система

- Токены: `background/surface/surface-secondary/primary/accent/text-primary/
  text-secondary/border/success/warning/danger`, светлая тема (см. `PRODUCT_DECISIONS.md`
  — зелёный акцент, светлый фон, курс на референсы уровня CALO).
- Базовые компоненты: Button, Input, Select, ProgressRing, MetricCard, Card,
  Modal/Drawer, Tabs, EmptyState, Skeleton, Toast.
- Применить к существующим экранам без смены их структуры/флоу — сначала
  визуальный слой, не функциональность.

Критерий готовности: все 8 экранов используют общие компоненты/токены, ни один
стиль не захардкожен инлайном поверх старого.

## Этап 4 — Редизайн экранов (используя новые данные из Этапов 1-2)

- Today/Dashboard: кольцо калорий, БЖУ-кольца, отдельно показан burned (тренировки),
  план на день — по референсам.
- AddFood/Result: список компонентов (Этап 2) в новом визуальном языке.
- AddWorkout: добавление подходов (миграция `workout_sets` из Этапа 5, если готова
  к этому моменту — иначе экран редизайнится без них и донастраивается следом).
- Progress: графики веса (скользящее среднее, если его ещё нет — проверить при
  реализации), недельная статистика калорий.
- Onboarding/Profile: та же дизайн-система, таймзона определяется автоматически.

Критерий готовности: каждый экран имеет loading/error/empty state, соответствует
референсам по качеству, мобильная раскладка (это Telegram Mini App) не ломается
на маленьких экранах/safe area.

## Этап 5 — Тренировочный модуль: схема и backend (ЗАМЕНЯЕТ старый Этап 5)

См. `DATABASE_MIGRATION_PLAN.md` раздел 5: `exercises`, `exercise_substitutes`,
`training_programs`, `training_program_days`, `training_program_exercises`,
`training_sessions`, `exercise_sets`.

- Миграция + сид стартовой библиотеки упражнений (20–40 штук по основным группам мышц,
  с `equipment_photo_url`/`technique_video_url` на внешние хостинги, `primary_muscles`/
  `secondary_muscles`, где уместно — несколько `exercise_substitutes`).
- Backend-домен `training`: CRUD программ/дней/упражнений, запуск/завершение сессии,
  запись подходов, история по упражнению (прошлые веса/повторения), личный рекорд.
- Адаптивное расписание: функция, выводящая типичные дни недели и время суток
  тренировок пользователя из `training_sessions.started_at` (по аналогии с
  `mealThreshold` в `notifications.ts`); используется день-лентой и напоминаниями.
- `workouts` (кардио/AI-оценка) не трогаем — остаётся отдельным путём для кардио.

Критерий готовности: можно создать/выбрать программу, запустить тренировку, записать
подходы по упражнению из каталога, увидеть прошлый результат и личный рекорд; после
3+ тренировок система видит типичные дни/время без ручной настройки.

## Этап 6 — Тренировочный модуль: экраны

Экраны по макетам с Artifact-канваса (жёсткий тёмный стиль, см. Этап 7):
- **Тренировки** (таб) — лента дней недели (с подсветкой «обычных» дней по адаптивному
  расписанию), карточка тренировки на сегодня, список упражнений, личный рекорд.
- **Тренировочная сессия** — текущее упражнение, ввод подхода (вес×повторения) с
  повтором прошлого значения одним тапом, таймер отдыха, переход между упражнениями.
- **Карточка упражнения** — фото оборудования, анимация/видео техники, схема тела
  (основные/вспомогательные мышцы), кнопка «Заменить» через `exercise_substitutes`.
- Нижняя навигация получает отдельную вкладку «Тренировки» (решение из макетов —
  Коуч перестаёт быть вкладкой первого уровня).

Критерий готовности: полный цикл «выбрал программу → начал тренировку → записал все
подходы → увидел это в истории упражнения» работает на реальном backend Этапа 5.

## Этап 7 — Редизайн v2: жёсткий спортивный стиль

Решение от 2026-11-13: светлый CALO-стиль (Этапы 3–4) не подошёл — нужен жёстче,
с упором на тренировки (60% веса интерфейса), без мягких теней/скруглений/Nunito.
Направление зафиксировано пользователем в `Nyami фитнес-приложение бриф/Nyami.dc.html`
(экспорт из отдельной сессии Claude Design по нашему брифу) — это финальный референс,
канвас-макеты из Artifact ему больше не актуальны.

- Токены v2: шрифты Onest (текст/заголовки) + Space Grotesk (числа) вместо Nunito;
  иконки Material Symbols Sharp; уменьшенные радиусы (10–18px вместо 22–28px);
  тонкая граница вместо soft-теней; тёмная тема по умолчанию (светлая — полный
  альтернативный набор токенов, переключается Telegram-темой).
- Today: тренировка — крупный герой-блок (план дня, быстрые метрики, CTA), питание —
  компактная сводка (донат + легенда) — готово.
- Применены новые токены/компоненты на: Today, Onboarding/Profile (форма профиля —
  степперы, выбор пола/цели/активности, ИМТ, карточка нормы), AddFood/Result
  (фото/галерея/штрихкод, текстовый ввод, редактирование ингредиентов), Progress
  (вес, калории за неделю, запись замера).
- Осталось в старом (v1) стиле: Coach (в референсе такого экрана нет — решение по
  нему отдельно) и AddWorkout (заменится реальным экраном тренировочной сессии
  из Этапа 6, пересобирать его дважды смысла нет).

Критерий готовности: ни один из экранов из списка выше не использует Nunito/старые
радиусы/soft-тени; визуально соответствует `Nyami.dc.html`.
